How it works

An AI window on one side, your console on the other.

Two small pieces. A plugin runs inside grandMA3 onPC and listens on localhost. An MCP server (Python, standard library only) is launched by your AI client and translates tool calls into requests to that plugin. Your AI client supplies its own model and credentials; nothing here needs an AI provider key.

The plugin

grandma3_ai_assistant.lua is a ComponentLua that opens the localhost bridge when you run Plugin <n> "Start". It reads objects, runs validated commands and Lua, and logs every undo group it creates.

The MCP server

companion_server.py exposes the tools (ma3_status, ma3_execute, ma3_lua and more), appends /noconfirm to console commands and keeps the change journal.

Your AI client

Claude, ChatGPT (through a tunnel), Codex or any MCP client. The client shows you previews and asks before it executes. It brings its own model and credentials.

Safety model

Built so a bad idea is cheap to take back.

An AI that can edit a live show needs guard rails. These are the ones the project actually implements. Always test on a copy of the showfile first.

01 PREVIEW

Preview before execute

ma3_execute with confirm=false validates and previews actions. The client shows you the plan and only then calls it with confirm=true.

02 NO POPUPS

/noconfirm handling

The MCP appends /noconfirm to every console command (also in batches and in Lua Cmd calls) so a console dialog cannot stall the bridge. Explicit /confirm is removed; quoted text is preserved.

03 UNDO

Journal and rollback

Every confirmed batch and every ma3_lua call runs in one Oops group and is written to journal.json. ma3_rollback undoes newest first and reports exactly what it could and could not undo.

04 LOCAL

Localhost only

The bridge binds 127.0.0.1:17844. Exposing it to a network is intentionally unsupported. Credentials and workflow data stay outside the showfile.

What a preview looks like

// AI calls ma3_execute with confirm=false
Store Group 21 /noconfirm
Label Group 21 "Movers Front" /noconfirm
// you read it, approve, then confirm=true runs it

Limits, stated plainly

Oops is a stack, so older entries cannot be undone while newer ones exist: roll back newest first. ma3_lua is open execution; snippets using Export, Save, SetVar, Keyboard, Mouse or RemoteCommand are flagged because Oops cannot undo them. If the plugin restarts, older undo ids are skipped.

Installation

Three parts, about ten minutes.

Part A installs the engine inside grandMA3 onPC. Part B or C connects your AI client to it.

Prerequisites

  • grandMA3 onPC on macOS or Windows, tested on 2.5.1.0. Other builds may work, but verify on the exact version you use.
  • Python 3 on the same computer (python3 --version, or python --version on Windows). No pip packages are needed.
  • An MCP-capable AI client: Claude Desktop, Claude Code, Codex CLI, or ChatGPT through a tunnel (Part C).
  • The onPC computer and the AI client run on the same machine, because the bridge is localhost only.
  • A copy of your showfile to experiment on.

Download grandma3-ai-plugin.zip   Release notes

Unzip it somewhere permanent, for example ~/grandma3-ai-plugin on macOS or C:\grandma3-ai-plugin on Windows. Your AI client will launch files from this folder, so do not move it afterwards without updating the client config. The server writes journal.json and snapshots/ next to itself.

A

Install the engine in grandMA3 onPC

The plugin is a Lua component that opens the localhost bridge. Based on the manual's Plugins topic.

  1. Copy the plugin files into the plugins library folder

    Put grandma3_ai_assistant.xml and grandma3_ai_assistant.lua together in gma3_library/datapools/plugins of the drive you import from. The manual says the XML and any extra Lua files must be in that folder (Folder structure).

    cd ~/grandma3-ai-plugin
cp grandma3_ai_assistant.xml grandma3_ai_assistant.lua \
   ~/MALightingTechnology/gma3_library/datapools/plugins/
    cd C:\grandma3-ai-plugin
copy grandma3_ai_assistant.xml C:\ProgramData\MALightingTechnology\gma3_library\datapools\plugins\
copy grandma3_ai_assistant.lua C:\ProgramData\MALightingTechnology\gma3_library\datapools\plugins\
    These are the default onPC locations listed in the manual (macOS: [System HD]/Users/[User Name]/MALightingTechnology, Windows: C:\ProgramData\MALightingTechnology). The manual also notes gma3_library sits inside that main folder. If you use a USB drive instead, the root folder is named grandMA3.
  2. Open the Plugin Pool and create a new plugin

    Open (or add) a Plugin Pool window through the Add Window pop-up, then edit an empty pool object using any edit method, for example Edit Plugin 1 on the command line. The Edit UserPlugin pop-up opens. Pick a free number; this guide calls it <n>.

    ManualPlugins: create a new pluginAdd window
  3. Import the XML

    In the editor tap Import, select the drive and grandma3_ai_assistant.xml, tap Import again, then close the editor. The plugin appears as grandMA3 AI Assistant with one Lua component named Assistant.

    If the import cannot find the Lua file: the manifest declares Path="grandma3_ai_plugin", so also try copying the .lua file into a grandma3_ai_plugin subfolder of the plugins folder. As a last resort, create the plugin by hand: add a New Component Lua, open it, paste the whole contents of grandma3_ai_assistant.lua, and name the plugin exactly grandMA3 AI Assistant (the plugin's Stop macro refers to this name).
  4. Start the bridge

    Run the plugin once in the showfile, from the command line:

    Plugin <n> "Start"

    or tap the plugin in the pool (the default argument is Start). The system monitor prints:

    grandMA3 AI Assistant: MCP bridge 2.0.0 listening on 127.0.0.1:17844

    On the first start the plugin also creates a macro named Stop AI Assistant in the first free macro slot (unless one already exists).

    ManualPlugin keyword
  5. Verify the port

    Without the AI client, check that something is listening on the bridge port:

    cd ~/grandma3-ai-plugin
./run_mcp_server.sh --check
# OK: grandMA3 bridge reachable at 127.0.0.1:17844

# or, by hand:
lsof -iTCP:17844 -sTCP:LISTEN
    netstat -ano | findstr 17844
# or, in PowerShell:
Test-NetConnection 127.0.0.1 -Port 17844
  6. Auto-start, stop and reload

    Stop the bridge with the generated macro Stop AI Assistant, or on the command line:

    Plugin <n> "Stop"

    Reload after editing the Lua: stop, then start again. If you edit external Lua files, ReloadAllPlugins rereads them from disk first (and the component's InStream/file update setting must allow it, see the Plugins topic).

    Plugin <n> "Stop"
ReloadAllPlugins
Plugin <n> "Start"

    Auto-start. The plugin has no built-in on-load hook, and I did not find a documented show-load trigger in the manual, so this guide does not promise one. The reliable way is one click: create a macro whose line is Plugin <n> "Start" and assign it to an executor or view button, then tap it after loading the show.

    ManualMacrosAssign object to an executor
    The Lua state is not saved in the showfile, so after reopening a show or restarting onPC you must start the bridge again.
B

Install the MCP server in Claude

Claude launches companion_server.py itself over stdio. Replace the folder in each command with where you unzipped the release.

Open Claude → Settings → Developer → Edit Config, or edit this file directly:

~/Library/Application Support/Claude/claude_desktop_config.json
{
  "mcpServers": {
    "grandma3": {
      "command": "python3",
      "args": ["/Users/YOU/grandma3-ai-plugin/companion_server.py"]
    }
  }
}

If Claude Desktop cannot find python3, use the absolute path from which python3. The bundled launcher is an alternative that also warns on stderr when the bridge is down:

"command": "/bin/bash",
"args": ["/Users/YOU/grandma3-ai-plugin/run_mcp_server.sh"]

Quit and reopen Claude Desktop completely after saving.

Edit this file (create it if missing):

%APPDATA%\Claude\claude_desktop_config.json
{
  "mcpServers": {
    "grandma3": {
      "command": "python",
      "args": ["C:\\grandma3-ai-plugin\\companion_server.py"]
    }
  }
}
Backslashes must be doubled in JSON. If python is not on PATH, use the full path to python.exe, or the launcher "command": "py", "args": ["-3", "C:\\grandma3-ai-plugin\\companion_server.py"]. Do not use run_mcp_server.sh on Windows unless you have Git Bash or WSL set up.

Quit Claude Desktop from the system tray and reopen it.

macOS / Linux
claude mcp add grandma3 --scope user -- python3 ~/grandma3-ai-plugin/companion_server.py
claude mcp list
Windows (PowerShell)
claude mcp add grandma3 --scope user -- python C:\grandma3-ai-plugin\companion_server.py
claude mcp list

Drop --scope user to register it for the current project only. Inside Claude Code, /mcp shows the connection state.

Verify with ma3_status

With the bridge running (Part A), start a new chat and ask:

Call ma3_status and tell me whether the grandMA3 bridge is running, the plugin version and the console version.

A healthy reply reports the bridge as running, plugin version 2.0.0 and your onPC version. If Claude lists the ma3_* tools but ma3_status fails, the MCP server works and the plugin is simply not running; go back to step 4 of Part A.

C

Install in ChatGPT / OpenAI and other clients

Be clear about the limit: ChatGPT connectors use remote MCP servers, while this server is a local stdio process that can only reach a localhost bridge. The repo's answer is a tunnel mode built on OpenAI's Secure MCP Tunnel (tunnel-client). I could not test it against a live ChatGPT account, so treat the ChatGPT-side steps as pointers to OpenAI's own documentation.

What start_grandma3_mcp.sh --tunnel does, taken from the script:

  • Checks that the bridge answers on 127.0.0.1:17844 (skip with --skip-bridge-check).
  • Requires tunnel-client on your PATH and a tunnel ID from OpenAI (--tunnel-id or the TUNNEL_ID variable).
  • Reads your OpenAI control-plane key from CONTROL_PLANE_API_KEY or prompts for it hidden. It never writes the key to disk.
  • If the profile does not exist, runs tunnel-client init --sample sample_mcp_stdio_local with python3 companion_server.py as the MCP command, then tunnel-client doctor, then tunnel-client run.
cd ~/grandma3-ai-plugin

# 1. Plugin must already be running in onPC (Part A)
# 2. Validate only, without starting the tunnel:
./start_grandma3_mcp.sh --tunnel --tunnel-id tunnel_your_id --doctor-only

# 3. Run it (keep this terminal open):
export CONTROL_PLANE_API_KEY="..."   # or let the script prompt you
./start_grandma3_mcp.sh --tunnel --tunnel-id tunnel_your_id

Options: --profile NAME (default grandma3-local), --plugin-port PORT, --doctor-only, -h.

Then, in ChatGPT: add the tunnel as an MCP connector following OpenAI's documentation for Secure MCP Tunnel and custom connectors. Availability depends on your plan and workspace settings, and I have not verified those screens, so they are not reproduced here.

Limitations. The script is Bash: use macOS, Linux, WSL or Git Bash (there is no native Windows launcher). ChatGPT only works while the tunnel terminal, onPC and the plugin are all running on your computer. The bridge itself still never leaves localhost; only the MCP server is exposed through the tunnel, so anyone able to use that connector can drive your show. Share it only with people you trust. Local mode, by contrast, needs no tunnel, key or internet.

Codex CLI can start local stdio MCP servers directly. Add this to ~/.codex/config.toml:

[mcp_servers.grandma3]
command = "python3"
args = ["/Users/YOU/grandma3-ai-plugin/companion_server.py"]

On Windows use command = "python" and a path such as 'C:\grandma3-ai-plugin\companion_server.py' (single quotes avoid escaping backslashes in TOML). Restart Codex, then ask it to call ma3_status. Newer Codex versions may also offer codex mcp add; check codex mcp --help for your version.

Any client that can launch a stdio MCP server works. The whole contract is: run this command, speak MCP on stdin/stdout.

python3 /path/to/grandma3-ai-plugin/companion_server.py

Optional environment variables for the MCP process (local troubleshooting only): GRANDMA3_AI_PLUGIN_HOST and GRANDMA3_AI_PLUGIN_PORT. Exposing the bridge to a network is intentionally unsupported. Files are written next to the server unless you override GRANDMA3_AI_NOTES_PATH, GRANDMA3_AI_JOURNAL_PATH, GRANDMA3_AI_PATTERNS or GRANDMA3_AI_STAGE.

Use ./start_grandma3_mcp.sh (local mode, no flags) to check the bridge and launch the same server; --doctor-only validates without running it.

First-run checklist

  • Working on a copy of the showfile, saved.
  • onPC shows MCP bridge 2.0.0 listening on 127.0.0.1:17844 in the system monitor.
  • The AI client lists the ma3_* tools.
  • ma3_status reports the bridge as running.
  • ma3_context returns your selection or selected sequence.
  • A harmless ma3_execute preview (confirm=false) returns the plan without changing anything.
  • You know where journal.json lives and how to ask for ma3_rollback.

Example prompts

Call ma3_status, then ma3_context, and summarise my selection and the selected sequence.

Troubleshooting

SymptomLikely cause and fix
ma3_status fails, tools are visibleThe plugin is not running. Run Plugin <n> "Start"; confirm with ./run_mcp_server.sh --check or netstat/lsof.
Warning: bridge not reachablePrinted by the launcher on stderr. Harmless if you start the plugin afterwards; the server connects per request.
cannot bind bridge in the system monitorPort 17844 is taken, usually by an instance already running. Stop it (Plugin <n> "Stop") and start again.
LuaSocket is unavailableThe plugin needs the socket Lua module from onPC. The build you are on does not expose it; this plugin cannot run there. Verify on onPC 2.5.1.0.
Import cannot find the Lua fileBoth files must be in gma3_library/datapools/plugins (see the note in Part A step 3), or paste the Lua into a new component by hand.
A command times outA console dialog is waiting. Commands should carry /noconfirm; the MCP adds it automatically, but macros stored in the show are not covered.
Client says the server failed to startWrong path or python3 not found by the GUI app. Use absolute paths, restart the client fully, and try the command in a terminal.
Rollback skipped entriesOops is a stack: roll back newest first, or pass force_oops. Entries from before a plugin restart cannot be undone with Oops.
After reopening the show it stopped workingThe Lua state is not stored in the show. Start the plugin again.
Behaviour changed after an onPC updateRe-run ma3_api with drift=true to compare the live API with api_index.json, and re-verify on a copy.
FAQ

Questions people ask first.

Is this official or affiliated with MA Lighting?

No. It is an independent, unofficial community project. grandMA3 and MA Lighting are trademarks of their owners. MA Lighting's technical support does not cover plugins or Lua scripts (see the Plugins topic).

Does it run on a real console or only onPC?

It is built and tested for grandMA3 onPC 2.5.1.0 only, because the bridge uses a localhost socket and the AI client runs on the same computer.

Do I need an OpenAI or Anthropic API key?

Not for this project. The AI client you use supplies its own model and credentials. Only tunnel mode needs an OpenAI control-plane key, which is read from your environment or terminal and never written to disk.

Can the AI delete or break my show?

It can change what the commands and Lua you approve can change. Previews, /noconfirm handling, Oops groups, the journal and snapshots exist to reduce the risk, but ma3_lua is open execution and some operations cannot be undone. Work on a copy, save often and read previews.

Does my show data leave my computer?

The bridge and the MCP server are local. What your AI client sends to its model provider is whatever tool results the conversation includes, such as fixture names and properties. Check your provider's data policy. The journal and snapshots stay on disk next to the server.

Why does the server append /noconfirm?

Console confirmation popups block a bridge call until someone taps them. Appending /noconfirm avoids that. The Store manual lists the option as /NoConfirmation; see the Store keyword.

Does it need pip packages or Node?

No. The MCP server, MVR reader and pattern learner are pure Python standard library.

Which license is it under?

The repository does not declare a license yet. Check the repository before redistributing.
